# 空間グリッド比較・変換基盤 開発指示書

## 1. プロジェクト概要

地域標準メッシュを中心として、複数の空間グリッド／空間インデックスを比較・可視化・変換できる基盤を開発する。

対象とする空間グリッドは以下の6種類とする。

- 地域標準メッシュ（JIS X 0410）
- H3
- S2
- Geohash
- XYZタイル
- 空間ID

成果物は次の2つとする。

1. Web GIS
2. QGISプラグイン

本プロジェクトは、単なるグリッド表示ツールではない。

地域標準メッシュで既に蓄積されている人口統計、経済統計、土地利用、農業、環境、防災などのオープンデータを、H3・S2・Geohash・XYZタイル・空間IDへ接続するための相互運用基盤を目指す。

## 2. プロジェクトの基本思想

### 2.1 地域標準メッシュを中心に据える

日本国内には、地域標準メッシュで整理された膨大なデータ資産が存在する。

そのため、空間IDなどの新しい体系だけを中心にするのではなく、地域標準メッシュを既存資産の起点として扱う。

想定する基本フローは以下のとおり。

```
地域標準メッシュのオープンデータ
        ↓
セルの交差・包含・面積比を計算
        ↓
H3 / S2 / Geohash / XYZ / 空間ID
        ↓
可視化・集計・変換・配信
```

### 2.2 単純な半透明重ね合わせを避ける

6種類のグリッドを一般的なGISのように半透明ポリゴンで同時表示すると、下層のレイヤーやセル境界が見えなくなる。

今回比較したい対象は、色の重なりではなく以下である。

- セル境界
- セル形状
- セルID
- 解像度
- 面積
- 階層構造
- 包含関係
- 交差関係
- 変換時の面積比

したがって、通常時はポリゴンを塗りつぶさず、枠線を基本とする。

## 3. 成果物

### 3.1 Web GIS

複数のグリッドを視覚的に比較し、地点やセルを選択してID、面積、交差関係などを確認する。

主な用途：

- グリッド方式の違いを理解する
- 同じ地点に対応する各グリッドIDを確認する
- セル形状と境界の違いを比較する
- 地域標準メッシュと他グリッドとの対応関係を調査する
- グリッド間変換を実行する
- 変換結果をファイルとして出力する

### 3.2 QGISプラグイン

実際のGIS業務で、グリッド生成、ID付与、空間結合、属性按分、対応表作成を行う。

主な用途：

- 表示範囲のグリッド生成
- レイヤーへのセルID付与
- 地域標準メッシュからH3などへの変換
- 面積按分
- 交差率の算出
- 対応表の作成
- GeoPackage、CSV、GeoParquet等への出力

## 4. Web GISの技術構成

### 4.1 フロントエンド

以下を基本構成とする。

- Vite
- React
- TypeScript
- MapLibre GL JS
- deck.gl
- Web Worker
- Turf.js
- 必要に応じてGeographicLib

### 4.2 グリッドライブラリ

候補は以下とする。

- 地域標準メッシュ：jismesh-js等
- H3：h3-js
- S2：JavaScript対応S2ライブラリ
- Geohash：ngeohash等
- XYZタイル：独自実装
- 空間ID：Spatial ID JavaScript SDK

特定ライブラリへ強く依存しすぎないよう、内部では共通インターフェースを設ける。

### 4.3 基本座標系

- グリッドID計算：各グリッドの正式仕様
- 内部座標：WGS84
- 地図表示：EPSG:3857
- 面積・距離：測地線計算または適切な投影座標系
- 日本国内の高精度処理：必要に応じて平面直角座標系

Webメルカトル上の平面面積を、そのまま正式なセル面積として扱わない。

## 8. モード1：メッシュ比較

### 8.1 目的

任意の2種類のグリッドを、同じ位置・縮尺・背景地図で左右比較する。

### 8.2 画面構成

```
┌──────────────────────────────────────────────┐
│ 左：地域標準メッシュ ▼    右：H3 ▼           │
│ 左：3次メッシュ ▼          右：resolution 8 ▼ │
├────────────────────┬─────────────────────────┤
│                    │                         │
│       左地図        │         右地図          │
│                    │                         │
└────────────────────┴─────────────────────────┘
                ← ドラッグ可能 →
```

### 8.3 実装方式

1枚のMapLibre地図をワイプする方式ではなく、2つのMapLibreインスタンスを同期させる。

理由：

- セル全体の形状を左右それぞれ確認できる
- 中央境界でセルが切断されない
- 左右で別々のグリッドレベルを扱いやすい
- 左右それぞれのレイヤー制御が容易

### 8.4 同期対象

- 中心座標
- ズーム
- Bearing
- Pitch
- 地図クリック位置
- マウスカーソル位置
- 背景地図
- 背景の明るさ
- 背景の透過度
- 選択地点

同期処理が無限ループしないよう、更新元フラグまたは同期ロックを設ける。

### 8.5 左右スライダー

中央の境界をドラッグし、左右の表示幅を変更できるようにする。

例：

- 左50%／右50%
- 左70%／右30%
- 左30%／右70%

### 8.6 グリッド選択

左右それぞれ、以下を選択可能にする。

- グリッド方式
- 解像度
- レベル
- 表示スタイル
- ラベル表示
- 親セル表示
- 子セル表示

### 8.7 解像度比較

以下の2方式を用意する。

**個別指定**

左右の解像度・レベルをユーザーが個別に選択する。

**面積一致**

左側のセル面積に最も近い右側グリッドのレベルを自動選択する。

各方式のレベル番号は直接比較できないため、固定対応表だけに依存しない。

クリック位置における実セル面積を計算し、最も面積が近いレベルを選択する。

### 8.8 セル選択

地図をクリックすると、クリック地点を含むセルを左右で選択する。

表示情報：

- グリッド方式
- セルID
- レベル
- 解像度
- 面積
- 中心座標
- 幅
- 高さ
- 辺長
- 親セルID
- 子セル数
- 隣接セル数
- 選択地点から中心までの距離

### 8.9 比較表

左右の情報を表形式で表示する。

例：

| 項目 | 左 | 右 |
| --- | --- | --- |
| 方式 | 地域標準メッシュ | H3 |
| ID | 644142883 | 882e... |
| レベル | 3次メッシュ | resolution 8 |
| 面積 | 0.94km² | 0.78km² |
| 親セル | 64414288 | 872e... |
| 子セル数 | 4 | 7 |

### 8.10 状態共有

以下をURLパラメータまたは共有IDとして保存できるようにする。

- 中心座標
- ズーム
- 左右のグリッド方式
- 左右の解像度
- 選択セル
- 背景地図
- 表示幅
- 表示設定

| --- | --- |
| 通常セル | 枠線のみ |

| 完全包含セル | 薄い単色 |

## 10. モード3：グリッド変換

### 10.1 目的

一つのグリッドで管理されたデータを、別方式のグリッドへ変換する。

### 10.2 変換元

- 地域標準メッシュコード付きCSV
- GeoJSON
- GeoPackage
- Shapefile
- GeoParquet
- Parquet
- QGISレイヤー
- Web GISで選択したセル
- R2上のデータセット

### 10.3 変換先

- 地域標準メッシュ
- H3
- S2
- Geohash
- XYZ
- 空間ID

### 10.4 変換方式

以下を実装する。

**重心割当**

変換元セルの重心が含まれる変換先セルへ割り当てる。

**最大重複面積**

変換元セルと最も大きく重複する変換先セルへ割り当てる。

**面積按分**

交差面積の割合に応じて属性値を分配する。

**全交差セルへ関連付け**

交差するすべての変換先セルとの対応関係を出力する。

**完全包含セルのみ**

完全に含まれるセルだけを対象とする。

**閾値指定**

指定した交差率以上のセルだけを対象とする。

例：

- 変換元：地域標準メッシュ
- 変換先：H3
- 変換方法：面積按分
- 対象属性：人口
- 最低交差率：1%

### 10.5 面積按分

例：

```
地域標準メッシュ人口：120人

H3-A：交差率37.8% → 45.36人
H3-B：交差率33.2% → 39.84人
H3-C：交差率29.0% → 34.80人
```

人口や世帯数などは、セル内で均等分布しているとは限らない。

面積按分結果には、必ず以下を付与する。

- 推計値フラグ
- 変換方法
- 交差率
- 注意事項
- 元データID
- 変換日時

必要に応じて、整数化方法を選択可能にする。

- 小数のまま
- 四捨五入
- 最大剰余法
- 合計値を維持する整数配分

### 10.6 出力項目

- 変換元グリッド方式
- 変換元ID
- 変換元レベル
- 変換先グリッド方式
- 変換先ID
- 変換先レベル
- 交差面積
- 変換元面積
- 変換先面積
- 変換元に対する交差率
- 変換先に対する交差率
- 元属性値
- 変換後属性値
- 変換方法
- 推計値フラグ
- geometry

### 10.7 出力形式

- CSV
- GeoJSON
- GeoPackage
- GeoParquet
- Parquet
- PMTiles

GeoPackageはブラウザ生成が困難な場合、WorkersまたはQGIS側で生成する。

## 11. 空間IDの3D表示

### 11.1 基本方針

XYZタイルと空間IDは、水平方向では同じ境界になる場合がある。

そのため、平面上に両方の枠線を描くだけでは違いを理解できない。

空間IDは高さ方向を含む3Dボクセルとして表示する。

### 11.2 必要機能

- 高度入力
- 高度スライダー
- 鉛直インデックス表示
- 最低高度
- 最高高度
- ボクセルの半透明表示
- 地上／地下切替
- 断面表示
- 俯瞰表示
- 高さ倍率調整
- XYZタイルとの水平方向一致表示

### 11.3 高さの基準

高さの基準面と単位を明示する。

例：

- 標高
- 楕円体高
- 地表面からの相対高
- 階数
- 任意基準高

異なる高さ基準を暗黙に混在させない。

## 12. 共通データモデル

### 12.1 セル

```typescript
type GridSystem =
  | "jismesh"
  | "h3"
  | "s2"
  | "geohash"
  | "xyz"
  | "spatial-id";

interface GridCell {
  system: GridSystem;
  id: string;
  level: number | string;

  geometry: GeoJSON.Polygon | GeoJSON.MultiPolygon;
  center: [number, number];

  areaM2: number;
  widthM?: number;
  heightM?: number;
  edgeLengthM?: number;

  parentId?: string;
  childIds?: string[];
  childCount?: number;
  neighbors?: string[];

  minHeightM?: number;
  maxHeightM?: number;

  metadata?: Record<string, unknown>;
}
```

### 12.2 交差関係

```typescript
interface GridIntersection {
  sourceSystem: GridSystem;
  sourceId: string;

  targetSystem: GridSystem;
  targetId: string;

  intersectionAreaM2: number;
  sourceAreaM2: number;
  targetAreaM2: number;

  sourceRatio: number;
  targetRatio: number;

  relation:
    | "contains"
    | "within"
    | "overlaps"
    | "touches"
    | "equal";
}
```

### 12.3 グリッドアダプター

```typescript
interface GridAdapter {
  system: GridSystem;

  pointToCell(
    longitude: number,
    latitude: number,
    level: number | string,
    heightM?: number
  ): GridCell;

  cellToGeometry(id: string): GridCell;

  getParent(id: string): string | null;

  getChildren(id: string): string[];

  getNeighbors(id: string): string[];

  cellsForBounds(
    bounds: [number, number, number, number],
    level: number | string
  ): GridCell[];
}
```

## 13. パフォーマンス設計

### 13.1 動的生成

全国分のセルを事前生成しない。

表示中の範囲だけを動的に生成する。

### 13.2 Web Worker

以下の処理はWeb Workerへ分離する。

- セル境界生成
- 大量ID計算
- 面積計算
- 交差判定
- レベル自動選択
- 対応表作成

### 13.3 表示中の制御

- パン中は再計算を抑制する
- moveend後に再計算する
- debounceを使用する
- 同一範囲・同一レベルはキャッシュする
- 表示セル数に上限を設ける
- 上限超過時はレベルを下げるよう案内する

### 13.4 推奨上限

初期値の例：

- 1レイヤーあたり最大5,000セル
- 全体で最大20,000セル
- 交差計算は最大10,000組
- 上限超過時はサーバー処理へ切り替える

数値は実測により調整する。

### 13.5 大規模処理

大規模処理は以下の流れとする。

```
ブラウザ／QGIS
   ↓ ジョブ登録
Cloudflare Workers
   ↓
Cloudflare Queues
   ↓
範囲・パーティション単位で処理
   ↓
結果をR2へ保存
   ↓
D1へ完了状態を記録
```

Workersで巨大なGeoJSON全体をメモリ展開しない。

## 14. データ配信形式

| 用途 | 形式 |
| --- | --- |
| 少数セルの表示 | GeoJSON |
| 表示範囲のグリッド | ブラウザ内生成 |
| 全国規模の表示 | PMTiles |
| 分析元データ | GeoParquet |
| ID対応表 | Parquet／CSV |
| QGIS成果物 | GeoPackage／GeoParquet |
| 一時変換結果 | R2 |
| Web表示用統計 | PMTiles／Parquet |

数式で生成可能なグリッド境界は、原則として事前配信しない。

統計属性などを伴う場合のみ、PMTilesやGeoParquetとして配信する。

## 19. UI／UX方針

### 19.1 基本方針

- 地図を主役にする
- 設定項目を常時すべて表示しない
- 詳細設定は折りたたむ
- グリッド方式ごとに一貫した色を使う
- 色だけで状態を表現しない
- 選択状態を線幅・線種・塗りでも示す
- モバイルよりPC・タブレットを優先する

### 19.2 画面構成

```
┌────────────────────────────────────────────┐
│ ヘッダー：モード切替・共有・エクスポート   │
├───────────────┬────────────────────────────┤

│ レイヤー設定   │                            │
│ 変換設定       │                            │
├───────────────┴────────────────────────────┤
│ 下部パネル：選択セル情報・比較結果          │
└────────────────────────────────────────────┘
```

比較モードでは、地図を左右2画面とする。

### 19.3 エラー表示

例：

- 現在の範囲ではセル数が多すぎます
- 解像度を下げてください
- 指定されたセルIDは無効です
- このグリッドは指定高度に対応していません
- 国際日付変更線をまたぐため表示を分割しました
- 面積按分値は推計値です

## 20. セキュリティ・運用

### 20.1 アップロードファイル

- ファイルサイズ上限を設ける
- MIME Typeを確認する
- 拡張子だけを信用しない
- R2へ一時保存する
- 有効期限後に削除する
- ファイル名をそのままR2キーにしない
- 任意コード実行につながる形式を処理しない

### 20.2 API

- レート制限
- ジョブサイズ制限
- セル数上限
- CORS制御
- 署名付きダウンロードURL
- ジョブ所有者確認
- 入力パラメータ検証

### 20.3 ログ

以下を記録する。

- 処理方式
- 変換元
- 変換先
- レベル
- セル数
- 処理時間
- エラー
- 出力ファイルサイズ

緯度経度やアップロード内容は、必要以上にログへ残さない。

## 22. プロジェクトの価値

本プロジェクトの中心価値は、複数のグリッドを並べて見せることではない。

以下を実現することが目的である。

> 地域標準メッシュとして蓄積された日本の統計・オープンデータ資産を、H3、S2、Geohash、XYZタイル、空間IDへ接続し、比較・検証・変換できる相互運用基盤を提供する。

各成果物の役割は次のように整理する。

- Web GIS：理解、比較、検証、共有
- QGISプラグイン：生成、分析、変換、実務利用
- Cloudflare：配信、大規模処理、ファイル管理
- 地理院地図：日本国内の基準背景地図
- 地域標準メッシュ：既存オープンデータ資産との接続点
